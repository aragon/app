# Semantic typography: decisions and exceptions

The review list for the typography layer (`source/typography.*.tokens.json`, generated into
`src/theme/tokens/typography.css`). Same idea as the colour decisions on the colour branch: what the owner decided, what
was decided provisionally with the reason and the alternative, the roles, and every exception with its pattern, its
places, its Today bundle against its role's bundle and an empty resolution column.

**Status values:** `OWNER` decided by the owner · `PROVISIONAL` decided by Claude on judgement, awaiting review ·
`OPEN` not decided, nothing built on it.

Sources: the typography analysis of 21 November 2026 (315 kit stories and 121 app screens measured at 1440 and 390 px,
every text element classified by purpose), and a second capture made for this work with a marker class in every class
literal, which tied each rendered element to the literal that sets its size, line height and weight.

## 1. Decided by the owner

| ID | Decision |
| --- | --- |
| O-01 | Today renders exactly as now, always. Nothing visible changes in the default typography. |
| O-02 | Fourteen roles, prefix `type-`: display; title-page, title-section, title-group, title-item; body, body-compact; supporting; caption; label, label-option; control (its steps follow the control size: `control`, `control-sm`); stat; tooltip. Modifiers `strong` (600), `numeric` (tabular figures), `mono`. A `prose` container for markdown. Responsive steps (phone, desktop from 768 px) live inside each role; `control` and `tooltip` are fixed. Colour stays a separate axis. |
| O-03 | Every text element takes the role of its purpose. Where today's rendering differs from the role's bundle, an exception of that role, named after the pattern, renders the place's current bundle in Today and the plain role in Next. Exceptions are grouped as far as the patterns allow and each is meant to be resolved later: dropped (take the role), moved to another existing role, or promoted to a new role or variant. |
| O-04 | Next (`[data-typography="next"]`): roles render their plain bundles in Sora (display, title-page, title-section, title-group, stat) and Inter Display (the rest). The faces load only in the kit's Storybook and in the app, never in the published kit. Letter spacing in Next only where clearly needed; Today has none. |
| O-05 | No visual change cleanups: the `font-medium` uses go (they render the 400 face); glyph sizes that follow a component's size (avatar initials, the permission graph's 10 px labels) stay as component-owned sizing, allowed by the lint. |
| O-06 | Scope: `packages/gov-ui-kit/src`, `apps/app/src`, `packages/assistant-chat/src`, `apps/docs/src`; third-party UI (the wallet modal) is out. |
| O-07 | (21 November 2026) Typography is its own preview axis, independent of the colour theme: `data-typography`, its own Storybook toolbar control and its own debug panel select and cookie in the app, ignored unless the `debugPanel` flag is on. |

## 2. Provisional decisions (made by Claude; review each)

| ID | Decision | Why | Alternative |
| --- | --- | --- | --- |
| P-01 | Utilities `type-<role>`; exceptions `type-<role>--<pattern>` (double dash), so an exception always reads as a variant of one role (`type-body-compact` is a role, `type-body--unstepped` an exception of `body`). | One spelling for the token path (`type.exception.<role>--<pattern>`), the class and the report; the generator rejects an exception whose prefix is not a role. | A separate prefix for exceptions (`typex-`). |
| P-02 | Each utility switches to its desktop values through Tailwind's own `md` variant (`@variant md` inside the `@utility`), reading `--type-<style>-md-*` variables. | In the app `md:` is a container query on the app column (APP-1143), not a media query; a media query on `:root` variables would step at the wrong width while the assistant is docked. The utility follows whatever `md` means in the stylesheet that compiles it. | Desktop variables inside `@media (width >= 48rem)` on `:root` (steps by viewport only). |
| P-03 | Today leaves the family and the letter spacing undeclared where they are the inherited defaults (`todayInherits`): the utility's `font-family: var(--type-x-font-family)` is then invalid at computed-value time and inherits. | A role must never override a family or spacing a parent sets (code, mono contexts); Next declares them. Two gauge column headings render tracking today: their exceptions declare it (the default rule does not hide a real value). | Declare Manrope everywhere (breaks inherited mono). |
| P-04 | Weight is declared by every role (400, tooltip 600); `type-strong` (600) sorts after the roles in Tailwind's order (it has fewer properties of the same group), so it always wins; `font-semibold` became `type-strong`. | Next must render the plain bundle; inheriting weight would leak a parent's 600. Checked: no rendered element inherited another weight, except markdown blockquote paragraphs (plugin weight 500), which got their own exception. | Leave weight inherited in Today. |
| P-05 | One exception renders one bundle. Places that share a bundle but not a pattern keep separate exceptions (e.g. `supporting--markdown` and `supporting--framework-leading`); scattered places of one shape are grouped under the analysis's patterns: `--unstepped` (keeps one size where the role steps up, analysis pattern 2), `--framework-leading` (Tailwind's built-in line height because no leading class is set, pattern 1). | Fewest exceptions that still name a pattern, never a look; a resolution then applies to a whole pattern. | One exception per component (more than 130). |
| P-06 | `control` and `control-sm` are two utilities; Button maps its `size` / `responsiveSize` to them per breakpoint (`h-8 type-control-sm`, `md:type-control`). | The step follows the control size, which can itself be responsive. | One control role plus size modifiers. |
| P-07 | Places that step at `sm` instead of `md` (DAO switcher, campaign stats) use a pair of fixed exceptions, the wide one behind `sm:` (`type-control--dao-name sm:type-control--dao-name-wide`). | Keeps their rendering exact at every width. | Move them to `md` (visible change between 640 and 768 px). |
| P-08 | Tailwind's built-in line heights a style keeps are explicit primitives (`--leading-default-*`, not theme values, so no `leading-*` utility), written as the same `calc()` Tailwind uses through a `ratio` extension. | The rounded number (1.5555555555555556) rendered 28.0001 px where Tailwind renders 28 px: 251 elements on 58 app screens differed until the ratio form. | Reference Tailwind's private `--text-lg--line-height`. |
| P-09 | The Next faces are self-hosted from catalog packages `@fontsource/sora` 5.3.0 and `inter-ui` 4.1.1 (the static InterDisplay files of Inter 4), both OFL-1.1, weights 400 and 600, through `.storybook/nextTypographyFonts.css` and the app's `layoutRoot/nextTypographyFonts.css`. The family names are token values in the published CSS (with the Manrope stack as fallback); the faces are not. | Browsers download a face only when text uses it, so Today never fetches them; the published package gains no font file or `@font-face`. | `@fontsource-variable/inter` with `font-variation-settings: "opsz" 32` (an extra property per role). |
| P-10 | Next letter spacing only for Sora at large sizes: display -0.5 px / -1 px, title-page -0.25 px / -0.5 px (phone / desktop). | Sora is wide; the other roles keep 0. | No spacing, or em-based spacing (DTCG dimensions are px or rem). |
| P-11 | Storybook gets its own Typography toolbar control (Today / Next) setting `data-typography`; the colour branch's theme switcher is not brought over (O-07), only `visual-diff`'s `--theme` option, byte-identical, plus `--typography`. The app gets the colour branch's `select` debug control (`debugProvider.api.ts`, `debugPanelControl.tsx` and its test, byte-identical) and its own `useTypographyPreview` / `typographyPreviewUtils`. | A later merge with the colour branch then only touches `preview.tsx`, `debugPanel.tsx` (one hook call each) and `layoutRoot.tsx` (one attribute each). | Bring the whole colour switcher. |
| P-12 | `Heading` takes `typeRole` (a role or an exception), not `role`, which is the ARIA attribute it already passes through. `size` keeps choosing the element and, without `typeRole`, the role (h1 title-page … h4 title-item, h5 supporting); it is deprecated for styling. All 36 kit, app and chat call sites now pass `as` and `typeRole`. | Backwards compatible; separates the element from the typography. | Rename `size` (breaking). |
| P-13 | The generated `typographyStyles.ts` spells out every class (`typographyClassNames`) for components that pick a style at runtime. | Tailwind only generates classes it finds in the source; `type-${role}` produced unstyled headings in the first screenshot run. | `@source inline()` with every class. |
| P-14 | The `prose` container maps its parts onto roles through markdown exceptions in `prose.css` (h1 … h6, p, strong, em, blockquote p), keeping the typography plugin's heading weights (800 / 700 / 600) and Tailwind's default line heights in Today. Lists and other parts the kit never styled stay on the plugin. | One place for authored content; Next shows plain roles. | A `type-prose` utility. |
| P-15 | The landing hero (`type-display`) keeps its fluid `clamp()` size, `leading-[1.2]` and `tracking-[-0.01em]` on top of the role; the file is allowlisted with exactly those classes. | A fluid size has no DTCG value; in Next the hero takes Sora but keeps its size. | A fixed display size (visible change). |
| P-16 | `type-numeric` is a no-op in Today (undeclared, inherits `normal`) and tabular figures in Next; it is on the stat figures (page header stats, summary card, stat card). | Shows the modifier without changing Today. | Leave it unused. |
| P-17 | Unstyled text (no typography class anywhere up the tree: it inherits the document's 16 px / 1.5) is not given a class in this pass; see section 5. | Each needs a source location the class-literal markers cannot give; adding classes blind risks inheritance changes. | Give every such element a role now. |
| P-18 | Third-party components keep their own overrides: in the help center, the classes passed to Fumadocs' `DocsTitle`, the page action buttons and the table of contents label (Fumadocs merges classes with tailwind-merge, which does not know `type-*`). In the assistant chat, the inline code's relative `text-[0.85em]` and the code block's `text-[13px] leading-relaxed` stay (code sizing, outside the lint's kit and app scope). | Out of scope like the wallet modal (O-06); a `type-*` class there would lose to the third-party classes. | `!`-important roles on Fumadocs components (no screenshot covers the help center). |
| P-19 | Class ordering (colour P-26/P-27/P-37–P-40): every role and exception utility has the same declarations, so between two `type-*` classes on one element the alphabetically later name wins; raw size, line-height and weight classes sort after them, the modifiers after the roles. Audit: every JSX `className` / `textClassName` holding a `type-*` class passed to a component (23 usages): none goes to a kit component that sets a `type-*` class on the same element (AddressOutput, Link's text, Collapsible set none). | The trap returns with every rename; screenshots only show default states. | Explicit typography props on kit components. |
