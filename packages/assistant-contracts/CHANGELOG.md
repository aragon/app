# @aragon/assistant-contracts

## 0.3.0

### Minor Changes

- [#1350](https://github.com/aragon/app/pull/1350) [`242489f`](https://github.com/aragon/app/commit/242489f2143c8d530f18d57dde73345509e07e23) Thanks [@tyhonchik](https://github.com/tyhonchik)! - Drop the Linear URL from the createLinearTicket tool output: users have no access to the Linear workspace, and anything in the output also reaches the model, which would narrate the link into the chat. The tool now returns only the ticket identifier — stored tickets and history entries from before the change still parse, the stale field is stripped.

- [#1394](https://github.com/aragon/app/pull/1394) [`c6e3d70`](https://github.com/aragon/app/commit/c6e3d7045295b954e619659e285ef43723c85eff) Thanks [@tyhonchik](https://github.com/tyhonchik)! - Answer product questions in the support assistant from the platform knowledge base (`aragon/platform-doc`, fetched at build time and bundled as an in-process search index): the agent searches and reads the documentation silently, says so and offers to pass the question on when it does not cover it, and a question the user agrees to pass on becomes a ticket under the `docs-gap` label.

- [#1394](https://github.com/aragon/app/pull/1394) [`c6e3d70`](https://github.com/aragon/app/commit/c6e3d7045295b954e619659e285ef43723c85eff) Thanks [@tyhonchik](https://github.com/tyhonchik)! - Refresh how the support assistant answers from its product knowledge. The corpus loader now leaves the base's `internal/` folder out (builder guidance, design principles, maintenance and product opportunities, excluded from user-facing content by the base's own workflow) and rewrites page links for a reader outside the wiki: a relative link into `protocol-doc/` becomes the public GitHub page of that file, any other relative link keeps its text only. The system prompt is rebuilt from the product owner's review of the first answers: one file per section (role, a routing table of what the user says and what the agent does, product answers, the ticket flow, tone, a closing reminder), about half the rules, each saying what to write with an example where the shape matters. Answers speak to the user in the second person, answer the question and stop, use plain words instead of product jargon or "features", turn a source table into sentences or a complete list, and give every link as markdown with a label. The Aragon team comes up in three situations only — something the app does not have, something the team sets up, a governance design choice — after the answer, in one sentence with the contact form, and none of the source's "paid", "no self-service" or "on request" wording reaches the user. A technical protocol question gets the high-level answer and the matching GitHub page as the OSx developer documentation; a question the documentation does not cover gets "I don't know", the facts at hand and one question about passing it on. The product is Aragon, never "Aragon App". Contracts: a message may be up to 8,000 characters (was 4,000), the same limit the widget now applies in the composer; every app-context value is one bounded line and the ticket fields have ceilings, so a hand-made request cannot push free text into the system prompt or an oversized body into Linear — the app context no longer enters the prompt at all, only the ticket.

    The agent model moves from `deepseek/deepseek-v4-flash` to `deepseek/deepseek-v4.1-flash`, served by the DeepSeek host first and Together AI second instead of Fireworks, which drops v4-flash on 2026-09-25: in a ten-scenario sweep the new model kept every prose rule the old one broke and answered in 4–6.5 s instead of 8–15 s. Search excerpts grow from 1,500 to 2,500 characters so a reference table reaches the model whole.

- [#1350](https://github.com/aragon/app/pull/1350) [`242489f`](https://github.com/aragon/app/commit/242489f2143c8d530f18d57dde73345509e07e23) Thanks [@tyhonchik](https://github.com/tyhonchik)! - Stop a stalled model from silently swallowing a turn. The AI Gateway only fails a call over to the next model when the upstream _errors_, and the failure actually seen in production is the opposite: the provider accepts the call and goes quiet, so nothing errors and nothing fails over — the same prompt on the same provider answered in 1.0s, 1.7s and 2.3s, then once in 47.8s, then once not at all. A turn now runs on the first model that actually starts answering: a model that produces nothing within its deadline is abandoned for the next one, which is invisible to the user (no content had arrived) and cannot duplicate a ticket (no tool had run).

    If every model stays silent, the wall-clock cap ends the turn — and that no longer fails silently either. The AI SDK closes such a stream with an `abort` chunk, which the widget renders as nothing at all: an empty message, no error, nothing in Sentry. It is now rewritten into a `timeout` error the widget can show, reported, and the turn is refunded so a retry does not cost the user twice. A stop from the composer aborts the stream the same way and is still left alone.
