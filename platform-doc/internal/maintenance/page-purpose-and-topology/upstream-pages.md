# Upstream page-purpose inventory

All 189 indexed upstream entries are retained read-only. This is an overlap and responsibility inventory for the [platform purpose audit](../page-purpose-and-topology.md), not a second factual review or an instruction to rewrite upstream. Every entry was inspected through its title, type, outline, links, and backlinks; relevant overlapping mechanisms received detailed reading. No protocol-to-platform backlink is required.

The ABI set contains 112 generated references and eight indexes. A repository-qualified symbol has its own reference even when another repository exposes the same name or an interface resembles its implementation. Exact signatures, constants, and source-level contracts remain upstream. The 69 other entries include concept explanations, protocol walkthroughs, source lookup, and their navigation.

## Layer and topic dispositions

| Topic comparison | Retained boundary |
| --- | --- |
| DAO / Account / Vault / execution | Upstream owns the contract and action-loop mechanics; platform pages explain acting identity, treasury use, intended actions, and the app experience. |
| Permission manager, auth, conditions / authorization model, OSx paths, scopes, viewer | Upstream owns resolution algorithms and condition contracts. Platform owns actor/path interpretation, division of authority, and indexed inspection. The existing recovery inventory preserves its qualified upgrade-route finding; this pass does not adopt upstream's unconditional no-ROOT permanence claim. |
| Plugin framework, factories, registries / app deployment and configuration | Setup, publication, registry internals, and factory choreography remain upstream. The platform explains what is supported, who arranges it, and how people configure or upgrade it. |
| IProposal, SPP / proposals, stages, status, and bodies | Shared interfaces and state transitions remain upstream; the platform owns the human model and named application pages. A product status is not a second protocol state machine. |
| Voting contracts and token mechanics / participation capabilities and guides | Exact thresholds, snapshots, delegation, and locks remain upstream. App controls, mechanism selection, availability, and material choices remain platform-owned. veLocker is not renamed or merged with LockManager. |
| Member Registry and metadata / names, profiles, identity inputs | Protocol custody and storage mechanisms remain upstream. User identity, app name lifecycle, and input behavior retain platform homes. |
| Unlinked matches: common membership, ratio, RuledCondition, protocol version, proxies, SelectorCondition | These were compared despite having no incoming platform links at baseline. They supply discovery, math, rule-engine, versioning, proxy, and direct-selector mechanisms; no missing product page or duplicated platform API follows from the absent links. |
| Unlinked deployment and signature topics | DAO Launchpad and Protocol Factory assemble deployments; they are not the app account-creation flow. EIP-1271 checks signatures; it is not a wallet connection transport. |
| Protocol guides and tooling / platform guides | Upstream walkthroughs operate contract interfaces or development tools. Platform guides help users choose and configure supported governance outcomes. Similar verbs do not establish duplicate guides. |
