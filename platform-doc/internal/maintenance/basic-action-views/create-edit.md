# Basic action create and edit inventory

Scope clarification (owner, 2026-09-13): A17–A18 belong to the BENQI-specific Gauge Registrar integration. The [client scope register](../client-specific-integrations.md) governs product coverage independently of the technical dispatch recorded below.

Evidence for the [basic-action audit](../basic-action-views.md), with the same A01–A22 identities in both inventories. This records source selection and required data; it does not establish deployment availability or successful execution. [Rendering paths, normalization, modes and fallback rules](./rendering-paths.md) apply to every row.

P = proposal editor; E = direct-execute editor; N = nested editor with DAO context (implemented but no current production opener); X = cross-chain destination editor. P/E/N merge core → installed-plugin → permission component maps. X still holds the core map, but has no DAO/plugin/permission context: it offers generic ABI/raw construction. No fresh specialized action is offered there. A raw/native-transfer allowlist item can still select TransferAssetAction without its required DAO context; this is a failing branch, not supported Basic composition.

For each row with a form, P/E/N select that form by the **exact editor runtime type**, subject to the stated map/data conditions. Missing map/type gives generic Decoded editing when inputData exists, otherwise Raw editing. Decoded/Raw are inspection modes when Basic is selected. Registry selector matches alone never install an editor.

## Other entry paths

WalletConnect sends the backend's decoded action directly to the editor, sets daoId, and clears meta; it does **not** call the JSON-import rehydrator. Successful specialized editing therefore requires the exact editor type and every required field in the response. Forms requiring meta cannot work through that callback as written. Decode failure preserves type `unknown` with inputData null and uses the generic Raw editor. See the [entry-path evidence](./rendering-paths.md#entry-paths-and-defaults).

The 2.11.2 UI-kit built-ins can also be selected by already-normalized types in edit mode, but they are display components, not purpose-built forms; they do not count as specialized creation support.
