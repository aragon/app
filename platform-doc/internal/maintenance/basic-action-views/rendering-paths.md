Selector lookup returns the first matching selector without target/network verification. Type lookup only returns descriptors with details components. The ten selector-bearing descriptors have ten distinct selectors; this does not prevent an unrelated contract having the same selector. The [details wrapper](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/components/proposalActionsItem/proposalActionsItem.tsx#L36) gives selector lookup precedence over type lookup. A selector match with no details component still selects its descriptor and passes `CustomComponent: undefined`; it does not retry type resolution. UI-kit built-in dispatch can still apply to the supplied type.

Editor selection is different: [ProposalActionsEditList](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/components/proposalActionsEditList/proposalActionsEditList.tsx#L57) indexes `customActionComponents[action.type]`; it never selects forms by selector. Core, plugin and permission maps merge in that order, later keys replacing earlier ones. The [core map](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/components/createProposalForm/createProposalFormActions/coreCustomActionComponents.ts#L14) has Transfer, TransferActionLocked, MetadataUpdate and MetadataPluginUpdate. The five plugin providers contribute seven other form identities; SPP contributes metadata picker defaults but no new component. The permission registry contributes ten more forms.

## Modes and fallback implementation

The installed [Item support checks and Basic dispatcher](./ui-kit-implementation.txt) establish:

1. Basic is supported when a CustomComponent exists **or** the action type is a key of the eight-type UI-kit enum. The dispatcher prefers CustomComponent, then transfer, mint, metadata, members and settings; otherwise it returns null. No ABI/selector check is performed by these built-in dispatch predicates.
2. Decoded requires inputData, excluding explicit RAW_CALLDATA and the pure native-transfer case (data `0x`, positive value, no parameters). Raw always exists. Initial mode is Basic → Decoded → Raw. The menu is rendered only when more than one mode is supported; therefore an always-visible three-option menu is not an accurate statement about every item in this package.
3. In edit mode, Decoded is WATCH when Basic exists, otherwise EDIT. Raw is WATCH when Basic or Decoded exists, otherwise EDIT. Read-only action surfaces use READ. ProposalActionsDecoder and its ABI parameter controls are generic fallbacks, never specialized Basic forms.
4. No general error boundary inside Item downgrades a selected but malformed Basic component. Missing context can leave loading/empty states or throw. Support is not evidence of valid data or authorized execution.

## Normalization and identity

[Default and plugin normalization](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/utils/proposalActionUtils/proposalActionUtils.ts#L101) invokes all registered normalization functions, not just installed plugin interfaces. Registration order is Multisig → Token Voting → Lock to Vote, followed by default conversion. The inventory records every input/output spelling.

- Transfer / TransferNative → WITHDRAW_TOKEN, amount converted from base units using token decimals. TransferActionLocked is editor-only and is not recognized by default detail conversion.
- MetadataUpdate / MetadataPluginUpdate → UPDATE_METADATA / UPDATE_PLUGIN_METADATA, with resource/avatar shape conversion.
- [Multisig conversion](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/plugins/multisigPlugin/utils/multisigActionUtils/multisigActionUtils.ts#L138) maps **both** member-action types to ADD_MEMBERS; UI-kit uses that type for the added/removed label and sign. Settings → CHANGE_SETTINGS_MULTISIG. [The hook](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/plugins/multisigPlugin/hooks/useMultisigNormalizeActions/useMultisigNormalizeActions.tsx#L18) reads member count for the first settings target and reuses it across that batch.
- [Token conversion](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/plugins/tokenPlugin/utils/tokenActionUtils/tokenActionUtils.ts#L145) maps Mint → TOKEN_MINT and UpdateTokenVoteSettings → CHANGE_SETTINGS_TOKENVOTE. [The hook](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/plugins/tokenPlugin/hooks/useTokenNormalizeActions/useTokenNormalizeActions.tsx#L20) requires a matching plugin for settings, including subplugins/linked accounts; otherwise it leaves the original type.
- [Lock to Vote conversion](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/plugins/lockToVotePlugin/utils/lockToVoteActionUtils/lockToVoteActionUtils.ts#L114) maps UpdateLockToVoteVoteSettings to the same CHANGE_SETTINGS_TOKENVOTE component shape, after the [same target-metadata guard](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/plugins/lockToVotePlugin/hooks/useLockToVoteNormalizeActions/useLockToVoteNormalizeActions.tsx#L20). It remains a distinct action/ABI.
- Execute, CreateProposal, gauge, registrar and campaign types pass through unchanged. CrossChainControllerForwardMessage is the editor spelling; CrossChainExecute is the backend/details spelling. No frontend normalizer converts between them.

[Selector derivation](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/utils/proposalActionUtils/proposalActionUtils.ts#L208) uses inputData function and parameter types; it does not read the first four calldata bytes. No selector is produced when inputData is absent, parameters are absent, or data equals `0x`. A mismatched decoded signature can therefore choose a different registry descriptor than raw calldata would imply. Account and plugin metadata share a selector but have no selector registration, so their distinct normalized types select the shared UI-kit component. The two voting-settings ABIs have different selectors despite their shared function name. The ten registry selectors are collision-free within this registration set.

[Nested tuple validation](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/utils/proposalActionUtils/proposalActionUtils.ts#L71) compares count, order, target, value and calldata. If any child differs, the **whole child array** becomes RAW_CALLDATA stubs, not only the mismatching child. An undecodable cross-chain message produces a warning in the outer Basic view; it is not silently interpreted as an empty valid batch.

## Entry paths and defaults

[Fresh picker selection](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/components/actionComposer/actionComposer/actionComposer.tsx#L279) attaches defaults, daoId and plugin meta. [useProposalActionsField](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/hooks/useProposalActionsField/useProposalActionsField.ts#L63) merges watched values with stable field IDs and does no type conversion.

[JSON import normalization](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/utils/proposalActionsImportExportUtils/proposalActionsImportExportUtils.ts#L167) explicitly rehydrates Transfer/TransferNative, multisig add/remove/settings, Token Voting settings and Mint. Metadata, Lock to Vote settings, gauges, campaigns and cross-chain messages all become Unknown. Without DAO context **every** decoded action becomes Unknown. Target plugin resolution is required for multisig/settings and a matching token plugin is required for Mint. [Top-level import](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/components/actionComposer/actionComposer/actionComposer.tsx#L212) then clears meta, breaking the otherwise-selected A06/A07/A08 forms. The dormant same-chain nested-import branch preserves it.

[WalletConnect](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/dialogs/walletConnectActionDialog/walletConnectActionDialogUtils.tsx#L45) accepts eth_sendTransaction, returns the single-transaction decoder response directly, or retains a raw `unknown` action after decode failure. Its [composer callback](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/components/actionComposer/actionComposer/actionComposer.tsx#L183) adds daoId and clears meta. It does not share JSON rehydration. The [backend entry point](https://github.com/aragon/app-backend/blob/107103b4cc9d8f778c78e09c7265f9a4ead89d6e/src/services/aragon-gateway/actionDecoder.ts#L10) confirms native-transfer special handling and ordinary decoding but is not evidence of the current production payload for every action.

[Nested reopen](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/dialogs/nestedActionsDialog/nestedActionsDialog.tsx#L98) preserves initial form actions; it decodes once only when every initial action lacks inputData. Cross-chain decoding omits DAO context. The sole current opener always supplies a destination network. ABI additions persist by network through the imported-contract provider.

## Picker, permission and client conditions

[ActionComposerUtils](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/components/actionComposer/actionComposerUtils.ts#L49) excludes linked-account plugin offerings for the selected target, filters items declaring requiredPermissionId against the account-as-who/target-as-where tuple, and separately composes permission-derived offerings. Renderer maps are not pruned by that item filter. Its permission map [deduplicates by permissionId](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/components/actionComposer/actionComposerUtils.ts#L202), retaining the last record per ID; multiple targets sharing an ID are not all offered. Registry permission matching is exact string equality, whereas the plugin item tuple comparison lowercases permission IDs. Neither path evaluates the attached onchain condition.

[Allowed action handling](https://github.com/aragon/app/blob/f8bf9e87260190aefd7d8a0eb59f72844e6e4502/apps/app/src/modules/governance/components/actionComposer/actionComposerUtils.ts#L266) preserves known target/selector picker items, special-cases native/ERC-20 transfer, otherwise produces CUSTOM_ACTION with decoded inputData or null. This affects picker contents, not eventual authorization. Generic added-contract ABI items keep CUSTOM_ACTION even when the registry knows that selector; no form is inferred from a name/ABI alone.
