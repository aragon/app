# Complete the account-terminology rollout

## User story

As a person setting up or governing an account, I want the app to use consistent names for the product entities I work with, so that I can follow its instructions and recognize the same account across screens.

## Context + benefit

The [account terminology rule](../../accounts/account.md#account-versus-dao) uses **account** for the product entity, reserving **DAO** for the OSx contract, exact protocol identifiers, and explicitly token-governed use cases. Generic product contexts in the current UI still use DAO-language.

The candidate would apply that distinction consistently, helping people connect labels and instructions without having to decide whether different terms describe the same entity.

Before ticketing, inventory user-facing uses of DAO and account, classify intentional protocol and token-governed references, and define the rollout scope and checks for inconsistent product copy.
