handoff/members-step-handoff.md is the deliverable. I re-derived every contract in it directly from this project's compiled candidate (_ds_bundle.js) and generated context rather than from memory:

Composition: one WizardPage.Step in the existing container, body = AddressesInput.Container + one AddressesInput.Item per row mapped from form state (the container clips children to its useFieldArray length, so hardcoded items silently break Add).
Prefill: wizard container defaultValues, row shape { address, name }; prefilled untouched rows are not validated on mount.
Editable vs resolved: onChange → item-local state only; onAccept (300 ms debounce, silent while ENS loads) → the row object at `${fieldName}.[${index}]`.
Invalid/duplicate: owned by addressesListUtils.validateAddress; duplicates compare slice(0, index) with isAddressEqual, so only the later row errors. Extend via customValidator returning a translation key.
Ownership: no FormWrapper, no nested wizard/container, no step-level <form> or submit.

Two verified additions this pass: ENS resolution is pinned to mainnet and enabled only when the effective wagmi config carries chain 1 with an ensUniversalResolver (a network-scoped wagmiConfig can disable ENS entirely), and the exact checksum-failure predicate.
