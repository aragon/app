Multisig Members Step.html — the step in a frame with a state switcher (empty / 3 members / invalid / duplicate) and a desktop/mobile-390 viewport toggle, plus a handoff section underneath.

Composition: the App-owned AddressesInput.Container/.Item (field array, add/remove, min-one-row, More menu, member error copy) over the kit's AddressInput, inside WizardPage. The only code I wrote is a wrapper that renders one .Item per field-array entry, plus prototype scaffolding.

Two honest caveats, also in the handoff:

The invalid and duplicate messages are the real validators' output (addressesListUtils.validateAddress), primed on load so they're visible without typing. ENS resolution and the on-accept path were not exercised — no wallet, no RPC, so the row avatar stays in its loading state.
AddressesInput.d.ts in the design system is a generic stub; I read the actual prop contract from the compiled bundle and listed it in the handoff.
