# Coding Guidelines

In addition to the coding rules enforced by `biome`, adhere to the following guidelines and conventions
throughout the coding process.

## Clean Code

- Remove all `console.log()` calls before committing code.
- Commented-out code should be removed and not committed.
- Whenever possible, use the
  [early-return pattern](https://gomakethings.com/the-early-return-pattern-in-javascript/#what-is-the-early-return-pattern)
  to improve code readability and reduce nesting levels.

## React Components

- Implement only one React component per file to maintain clarity and organization.
- Always use React Function Components for consistency and simplicity.
- Always use TypeScript and the `.tsx` extension for React components to leverage type checking.
- When a component becomes too large, consider splitting it into multiple sub-components to improve readability and
  maintainability.
- Treat tests as a composition signal: if a test cannot target a node by role, label or text — and reaches for a
  `data-testid`, a CSS selector or DOM traversal instead — the composition is too dense. Split the component rather
  than adding a handle, so assertions stay available at that level. See
  [testing](../projectDocs/testing.md#what-a-test-may-assert).
- When a component requires multiple files (e.g. tests, definitions), locate all files within the component folder.

## Responsive Layout

The application does not own the whole browser window: the AI assistant docks beside it as an in-flow
column, so the pane the app lays out can be much narrower than the viewport. The breakpoint variants
therefore measure the **application column**, not the browser — see
`src/modules/application/components/layouts/layoutRoot/breakpoints.css` for the mechanism and
[APP-1143](https://linear.app/aragon/issue/APP-1143) for the collision it fixes.

- `sm:` … `2xl:` and `max-sm:` … `max-2xl:` are container queries on the `app` container that
  `layoutRoot.tsx` declares on the application column. The thresholds are the design system's
  (40/48/64/80/96rem), so with the assistant collapsed the column is laid out exactly as the window
  would have been. Write responsive classes as usual: they do the right thing inside the column, and
  so do gov-ui-kit components, whose utility CSS is generated by this build.
- `body` is the fallback `app` container: the assistant panel, dialogs and anything else portalled to
  the document body measure the window, as they always did.
- **Surfaces that must measure the window wherever they render use `screen-*` / `screen-max-*`**: the
  assistant shell's docked-versus-fullscreen decision (its CSS and its `matchMedia` a11y logic must
  agree) and fixed-position overlays rendered inside the column, such as the debug panel. Do not
  express that with `min-*`, `max-[…]` or raw `@media` instead: they are viewport queries too, but
  they read like the container variants and hide the intent.
- A decision shared between the column and a portalled surface cannot be expressed in CSS — the two
  measure different things. Make the portalled surface unconditional instead of mirroring the query,
  see `navigationDaoUtils.getDefaultLinks`, where the dialog lists every destination because the bar
  drops its inline links on the column width.
- Tailwind's built-in container variants (`@sm:` … `@7xl:`, a different scale) query the nearest
  container of *any* name, which inside the app is the application column unless the component
  declares its own `@container`. Only use them together with such a declaration.

## React Component Properties

- Treat component props as read-only and avoid modifying them within the component.
- Always prefer passing content between components using the `children` property rather than custom props.
