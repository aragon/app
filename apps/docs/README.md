# @aragon/docs

Public site of the Aragon platform knowledge base, served at [app.aragon.org/help](https://app.aragon.org/help) through the app's rewrite (APP-1133). The content lives in [`aragon/platform-doc`](https://github.com/aragon/platform-doc) (private, branch `development`) and reaches the site at build time only, through [`@aragon/docs-corpus`](../../packages/docs-corpus/README.md) — the same loader and filter the assistant indexes with, so both publish the same pages. A static [Fumadocs](https://fumadocs.dev) export (Next.js, `output: 'export'`, `basePath: '/help'`): no server, no analytics, no error tracking, no link back to the private repository.

## Development

```sh
DOCS_CORPUS_DIR=../../../platform-doc pnpm dev   # reads a local checkout; without it, fetches the repository
pnpm build                                        # content → next build → output check, out/ is the site
pnpm test                                         # jest (node environment)
pnpm type-check
pnpm lint
```

`pnpm dev` serves the site on port 3001, where the app's local config (`NEXT_PUBLIC_DOCS_URL`) looks for it. `pnpm dev` and `pnpm build` start with `pnpm prepare:content` (`src/content/prepareContent.ts`), which resolves the corpus — the checkout `DOCS_CORPUS_DIR` names, otherwise a shallow fetch into the git-ignored `.docs-corpus/` with `DOCS_REPO_TOKEN` or the git credentials of the machine — keeps the pages the environment's mode publishes and writes them into the git-ignored `content/docs/` (one markdown file per page, a `meta.json` per folder) and `public/` (a `.md` copy of every page, `llms.txt`, `llms-full.txt`). `src/content/buildContent.ts` holds the rules; `pnpm check:output` fails the build when a page is missing from `out/`.

**Mode.** `DOCS_ENV` (`config/.env.*`, copied to `.env.local` by `pnpm setup <env>`) names the environment; `docsCorpusModes.site` in `@aragon/docs-corpus` maps it to a corpus mode: production publishes the pages the product owner validated (`ready`), every other environment adds the pages under review (`drafts`) and shows them with a "Draft" callout. `internal/`, the operating files and `protocol-doc/` are never published.

**Pages and links.** Area `index.md` files are the landing pages and set the sidebar order (their pages in the order they link to them; the root `index.md` orders the areas the same way and is the home page); pages an index does not link to follow by path. Links are resolved by `resolveSiteLink`: a page on the site becomes its route (`accounts/account.md` → `/help/accounts/account`, fragment kept), a page the mode does not publish becomes plain text, a protocol page goes to its GitHub page, absolute links stay.

**In the app.** The app serves the site at `/help` through its proxy (`apps/app/src/proxy.ts`) while the `helpCenter` feature flag is on, rewriting to the origin `NEXT_PUBLIC_DOCS_URL` names in `apps/app/config/.env.*`; the support chat passes the same flag to the assistant as `features.docsLinks`. The site has none of the app's navigation, so its header and footer link to the app at `NEXT_PUBLIC_APP_URL` (`config/.env.*`), next to the developer documentation and the website, the way docs.aragon.org does.

**Theme.** The look of docs.aragon.org on the Fumadocs layout (sidebar, search, table of contents, breadcrumbs, previous/next, page actions). `src/app/globals.css` imports the `@aragon/gov-ui-kit` primitives (colors, radii, spacing, type scale, the Manrope faces) in place of the Tailwind defaults, maps the Fumadocs semantic colors onto them and adjusts the few elements the kit styles differently (links, inline code, the search field, the table of contents); Roboto Mono, the code font, comes through `next/font` in `src/app/layout.tsx`. The site is light only, like the kit, so the theme switch is off. The header shows the Aragon wordmark of the app (`src/components/aragonLogo.tsx`) and the footer is `src/components/siteFooter.tsx`; every page offers its markdown copy through the Fumadocs page actions (copy, open in an assistant). On the landing pages, a list whose every item leads with a link is rendered as a card grid (`src/lib/remarkLinkCards.ts`, wired in `source.config.ts`; the item's link is the card title, the text after the dash its body); the areas carry a Lucide icon in the sidebar (`areaIcons` in `src/content/buildContent.ts`, written into their `meta.json`).

## Deploy

Through the shared `deploy-vercel` workflow of [aragon/github-templates](https://github.com/aragon/github-templates) (`workspace: apps/docs`, vaults `kv_docs_*`, Vercel project `platform-doc-ui`). Next writes the export at the root of `out/` whatever the base path, while Vercel's Next.js builder maps `/help/*` onto the filesystem as is (a rewrite reaches the pages but not `/help/_next/static/*`), so `pnpm nest:output` moves the export under `out/help/` after the build; the app only ever requests `/help/*`. The builder's own not-found route for the base path never matches (its pattern lacks the leading slash) and a `rewrite` to the 404 page would answer 200, so `vercel.json` adds an error-phase route that serves `/help/404`, the site's own not-found page (the builder's output path of `404.html`), with status 404 for every unknown `/help/*` path. `docs-development.yml` on every merge to `main` touching the site (`docs` filter in `.github/filters.yml`), on the `docs-updated` dispatch from `aragon/platform-doc` and by hand; `docs-production.yml` by hand only (`workflow_dispatch`); `app-preview.yml` deploys a preview when a pull request touches `apps/docs`. The workspace has no version and no changesets: production is whatever `main` builds from the validated pages at the time of the dispatch.
