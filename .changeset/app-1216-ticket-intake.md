The system prompt is four short sections (role, answering questions, tickets, tone), each rule said once, at less than half its former length. A ticket is a problem or request about Aragon that the team can act on. An errand between people, a joke or an empty "create a ticket" gets a soft question, and "the app is slow" gets one concrete question before a draft. The ticket fields are the assistant's account of what the user saw. It takes wording that matches what happened, leaves out guessed causes, jokes and names, and keeps to that when the user insists. It asks for a way to be reached once, in its own words, and not when the user already gave one. A draft interrupted by another question opens again after the answer. A capability the app lacks gets a plain answer and the contact link instead of "I don't know". How the draft card behaves now lives in the ticket tool's description and field descriptions, and the off-topic tool no longer flags product questions when the documentation tools are off. Production answers documentation questions from the draft pages too, as every other environment does; the public docs site keeps showing the reviewed pages only. The eval checks every reply for foreign links, bare URLs, talk about the documentation, friction words and "Aragon App", asks the judge yes-or-no criteria instead of scores, and runs conversations from real chats and from attacks (prompt extraction, an instruction inside a report, a phishing link).
