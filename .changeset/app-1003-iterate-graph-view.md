Add the DAO permissions graph view backed by real permissions data, including filter handling for enriched condition metadata, inactive plugin cleanup, DAO-connected plugin edges, restored DAO self-permission placement, the incoming-permission trident layout, and adaptive graph routing/fit behavior. Proposal-creation permissions on governing bodies render as per-target creator nodes (Anyone shown with the members icon, multisig as "Members of …", Safe and plugin creators keeping their body styling), stay visible under both permission filters, and surface their condition labels; the Safe logo now also renders in the list view. Both views render the same dataset under the same toggles — the graph no longer subsumes create-proposal grants that share a body with an open Anyone grant. Address details across the list rows and graph detail panels render their copy and block-explorer affordances through the shared definition-list component, adding explorer links to the graph permission panel. Row visibility is now governed by exactly the two toggles: "hide permissions granted to the DAO" keys off the holder, and "hide permissions on governing bodies" hides rows whose target is a subplugin — no implicit residual/unresolved/inactive pre-filters remain, so the list and graph show every other permission the DAO records. Permissions fetch failures now surface an error state instead of an empty "no permissions" view, and the page stays behind the `permissionsPage` feature flag.
